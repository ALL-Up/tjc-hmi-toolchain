# 避坑清单

每一条都是实际踩过的坑。按「症状 → 原因 → 解法」组织，遇到问题先来这里查。

---

## 一、上位机打开 / 编译阶段

### 报「错误的资源文件或者资源文件已经受损」

按顺序排查三层：

1. **容器层**：目录表只更新了一份。`0x000` 和 `0x08000`（正确应为 `0x080000`）
   两处必须**逐字节相同**。
   → 跑 `scripts/build_sorter.py` 里的 `selfcheck_container()` 定位。
2. **容器层**：目录 CRC 用错算法。必须用 `crc7950`（逐 32 位字）+ 盐 `"ADEC"`，
   **不是**逐字节的 `tjc_crc32`。
3. **`.pa` 层**：控件组格式错。常见三种：
   - 组头写成 `att-28`（控件实际是 `att-39` / `att-22` / `att-42`）
   - 数字控件 `type` 写成 `0x6E`（正确是 `0x36`）
   - 索引块偏移少算 `12N`（`索引项[0] = 12N + len(页面组) + 12`）
   → 跑 `scripts/verify_truth.py` + `hmi_inspect.py` 定位。
4. **`.pa` 层**：头部 `+0x00` 校验值错 → 用 `pa_codec_v5.page_checksum()` 重算。

### 编译报「font 初始值无效:字库ID无效」

容器里没有 `0.zi` 字库成员。**即使 `font=0` 也会报**，每个带 font 的控件一条错误。

解法：整块借用合法字库（见 `docs/HMI_FORMAT.md` §6），
并在 `main.HMI` 名字表加 `"zi" + "0.zi"` 条目。

### 加载时弹「索引超出了数组界限」

`font` 用了工程不拥有的字体索引。无字库工程只有内置字体 0，`font=1..4` 会弹。

### 弹「objedit ref error! 参数无效」

`txt_maxl < len(txt)`。`txt_maxl` 必须 ≥ 文本实际长度，否则**每个超长文本控件弹一次**。
（本项目曾因两个 12 字节文本超默认 10 → 恰好弹 2 次。）

### 上位机会独占锁定 `.HMI`

替换文件前必须先关闭上位机。若已被锁定，用共享读绕过：

```python
k32 = ctypes.windll.kernel32
k32.CreateFileW.restype = ctypes.c_void_p      # ⚠ 必须设，否则句柄判空失败
h = k32.CreateFileW(path, 0x80000000, 1 | 2 | 4, None, 3, 0, None)  # SHARE_READ|WRITE|DELETE
if h in (0, 0xFFFFFFFFFFFFFFFF):
    raise PermissionError(path)
```

`hmi_inspect.py` 的 `load()` 已内置该逻辑。

## 二、`.pa` 页面格式

| 坑 | 说明 |
|---|---|
| **索引块占位忘算** | `索引项[0] = 12N + len(页面组) + 12`，漏了 `12N` 则整体错位 |
| **组顺序错** | 索引块之后**先放页面组**，再放控件组 |
| **控件组头写错** | 文本/数字 `att-39`、图片 `att-22`、按钮 `att-42`，都不是 `att-28` |
| **事件槽数写错** | 控件只有 2 个槽（页面 5 个） |
| **数字 type 写成 `0x6E`** | 正确是 `0x36` |
| **`time` 当成 DWORD** | 是 WORD |
| **`val` 宽度混淆** | 数字控件 `val` 是 DWORD(4)，**按钮 `val` 是 BYTE(1)** |
| **页面 `objname` 留空** | 值应为 `"page0"` |
| **`+0x38` 照抄常数** | 实际 = `12 × nobj`，随对象数变化 |
| **多页页名重复** | 每个 `.pa` 的页名必须不同（`page0`/`page1`），重名会显示成 `page00` |
| **`txt` 未转 GBK** | 中文文本必须 GBK 编码写入 |
| **多行事件代码写法** | 见 §3 |

### 数字控件类型用错是「静默失效」

用文本控件承载序号/数量时，`.val=` 永远不生效，屏上不动，也没有任何报错。
**这是最常见的丢分点。**

## 三、事件代码

❌ **错误做法**：把代码内嵌进值区（`plen = 16 + len(code)`，名称补齐到 16）。
编辑器读不出，事件框显示为空 —— 但因为未编辑的组字节被原样复制，
文件里「看起来格式还在」，很容易误判为正确。

✅ **正确格式**：

```
槽名后缀 = 代码行数
  codesdown-0  → 0 行（空）
  codesdown-1  → 1 行

代码行 = 独立的纯名记录，plen = len(行文本)，无 NUL 无换行
        "page 1" → plen = 6

槽顺序：codesdown-N → 代码行 → codesup-N → 代码行 → 组尾 4 NUL
```

### `sendkey` ≠ 页面跳转

`sendkey=1` 只是触摸时往串口发 7 字节包：
`0x65 页 控件 事件 FF FF FF`。

**跳页需要 MCU 收包后发 `page N` 回来。** 调试模式（无 MCU）点 sendkey 控件
看起来「没反应」，这是正常的。

屏内自跳页必须写控件**事件代码**。

## 四、图片

### 图片不显示

分两层排查，**先查登记清单，再查成员格式**（登记比格式更上游）：

1. **画布层**：`main.HMI` 名字表缺 `.i` 条目，或容器缺 `.i` 成员
   - 只放 `.ib`、或放了 `.is + .ib` 但名字表没登记 `.i` → **全都不显示**
2. **屏上层**：图片未下载，或 ID 与代码表顺序不符

### 透明图四周有黑边

`.i` 是 RGB565，**没有 alpha 通道**，透明像素 → `0x0000` = 黑。

解法：素材**全不透明**。按钮四角填背景图对应位置的切片色可做到视觉无缝。

### 图片三件套一个都不能少

一张图需要 `.i` + `.is` + `.ib`：
- `.i` = 屏显 RGB565（画布渲染真正入口）
- `.is` = PNG 原件
- `.ib` = 图库

名字表**只登记 `.i`**，`.is`/`.ib` 登记上去反而可能出问题。

## 五、按钮控件

| 坑 | 说明 |
|---|---|
| **`sta=1` 时 `pic` 被忽略** | 按钮默认 `sta=1` 是色块模式，设了 `pic` 也显示灰块。**必须 `sta=2`（图片模式）** 才渲染 `pic`/`pic2` |
| **属性序列与 TEXT/NUM 不同** | `att-42` 顺序见 `docs/HMI_FORMAT.md` §3.5，`sta style borderc borderw font` 中间没有 `key` |
| **`val` 是 1 字节** | 数字控件的 `val` 是 DWORD，按钮的是 BYTE |
| **双态图** | `pic`/`picc`/`bco` = 常态，`pic2`/`picc2`/`bco2` = 按下态 |

## 六、素材绘制

- **中文字体**：Windows 用 `C:\Windows\Fonts\msyhbd.ttc`（微软雅黑 Bold）；
  Linux 用 Noto CJK；macOS 用 PingFang。`draw_assets.py` 内置回退链。
- **超采样抗锯齿**：图形按 4× 尺寸绘制再 `resize(LANCZOS)` 缩回。
- **不要用 `Image.new("RGBA")` 产出透明底后直接转 `.i`** —— 会得到黑边。

## 七、烧录与运行

| 现象 | 原因 |
|---|---|
| 屏无反应 | 屏 RX 没接 MCU TX / 未共地 / 波特率不一致 / **出厂 demo 还在** |
| 只显示部分控件 | 某条指令缺 `0xFF` |
| `.val` 不更新 | 用了文本控件而非数字控件 |
| 文字乱码 | 中文无 GB2312 字库，或源码编码不符 |
| 指令无效 | 参数写了 `0x` 前缀 |

### 关键提醒

- **必须刷掉出厂 demo**，否则与 MCU 指令抢屏。
- 串口下载波特率 `115200`（与运行波特率无关）。
- 图片/字库在**下载时**随工程写入屏内 Flash，改了要**整体重新下载**。
- 接线：USB-TTL 的 TX → 屏 RX，**GND 必须共地**，屏单独 5V 供电（别从模块取电）。

## 八、通用方法论

这些坑能挖出来靠的是以下习惯，值得复用：

1. **先写回归测试再改代码。** 用真值重建做逐字节比对，
   把「格式是否正确」变成可自动判定的布尔值。
2. **逐组而不是整页比对。** 整页 diff 只告诉你「有差异」，
   逐组 diff 直接告诉你「哪一组错、错在第几字节」。
3. **拿真值反推优于盲猜。** 请用户在上位机手拖一次控件存一份，
   胜过十轮猜测；单次试错要用户手动开上位机验证，成本全压在用户身上。
4. **用户在编辑器里保存过的生成文件 = 最高价值真值。**
   diff 生成版 vs 保存版能一次看清编辑器改了什么。
5. **未编辑 ≠ 已解析。** 编辑器对未修改的组**原样复制字节** ——
   「我的格式还在文件里」不代表「编辑器认这个格式」。要看它重写过什么。
6. **先查登记清单，再查成员格式。** 登记清单比格式更上游
   （图片三轮失败全是因为名字表缺 `.i` 条目，而不是字节格式错）。
7. **三级探针隔离法**：无损 rebuild → 改 1 个字符 → 换整个成员。
   三步让用户依次验证，能把「容器层 / 替换机制 / 成员内容」彻底隔离。
