# 淘晶驰 USART HMI 串口屏工程工具链

用**纯代码**生成淘晶驰（TJC）串口屏 `.HMI` 工程文件的工具集 —— 不用鼠标在界面上拖控件，
直接写出二进制工程，交给上位机打开、编译、下载。

本项目来自一个真实项目（工创赛智能分拣装置，屏型号 `TJC4827T143_011R_P20` / 480×272）
的完整逆向与实现过程。**所有格式结论都经过与上位机真值样本的逐字节比对验证**，
回归测试脚本随仓库提供，可复现。

> 核心价值：`.HMI` 是淘晶驰私有的 CFS 容器格式，`.pa` 页面格式亦未公开。
> 本项目把两者从零解出并实现了可用的编码器 + 生成器 + 检查器 + 本地验证器。

## 快速开始

```bash
pip install pillow pyserial        # pillow 画素材 / pyserial 连屏

python scripts/verify_truth.py     # ① 先确认编码器正确（回归测试，应全部 PASS）
python scripts/draw_assets.py      # ② 生成素材 PNG 到 out/assets/
python scripts/build_sorter.py     # ③ 生成 out/sorter.HMI + 容器自检 + 真值回归

python scripts/hmi_inspect.py out/sorter.HMI --mcu           # ④ 检查成员表/名字表/页面组 + MCU 指令骨架
python scripts/i_to_png.py out/sorter.HMI out/png --montage  # ⑤ 屏内图片解成 PNG，肉眼看清楚画的是什么
python scripts/tjc_sim.py --dry-run                          # ⑥ 打印 MCU 指令字节流（不接硬件）
python scripts/tjc_sim.py --port COM5 --scenario full        # 接屏实测
```

产物 `out/sorter.HMI` 用淘晶驰上位机打开 → 编译 → 下载即可。

## 这个项目解决了什么问题

淘晶驰的工程文件格式不公开。典型痛点：

| 痛点 | 本项目 |
|---|---|
| 只能在上位机手工拖控件，无法批量/程序化生成 | 纯 Python 生成完整 `.HMI`，含多页面、图片、按钮事件 |
| 手改二进制后上位机报「错误的资源文件或者资源文件已经受损」，无从下手 | 已解出全部校验：`.pa` 5 段累积 CRC、CFS 目录 `crc7950 + "ADEC"`、`main.HMI` 五段 CRC |
| 图片「放进去但不显示」，不知道差在哪 | 定位到关键：`main.HMI` 名字表必须登记 `.i` 条目 |
| 按钮设了图片却显示灰块 | `sta` 必须为 2（图片模式），`sta=1` 时 `pic` 被忽略 |
| 事件代码写进去编辑器读不出 | 解出真实格式：槽名后缀 = 行数，代码行是独立记录 |
| 改了工程后编译报「font 初始值无效」 | 工程必须实际含 `0.zi` 字库成员 |
| 没有硬件就没法验证 | `tjc_sim.py` 用 pyserial 直接驱动屏 |
| 生成的文件对不对没法判定 | 回归测试把「格式是否正确」变成可自动判定的布尔值 |

## 已验证的格式结论（摘要）

完整规范见 [`docs/HMI_FORMAT.md`](docs/HMI_FORMAT.md)。

### `.HMI` 容器（CFS v2）

```
0x000000  主目录    = u32 count + count×28B 条目 + u32 目录CRC
0x080000  目录副本  ← 必须与主目录逐字节相同（只写一份会被判「资源受损」）
0x380000  FF FF FF FF
0x6FFFF8  "ver21234"（固定魔数）
0x700000  数据区，成员首尾相接、无填充，末成员结束即 EOF
```

目录条目 28B：`16B 名称 + u32 绝对偏移 + u32 大小 + u32 类型标记`
（类型标记与内容无关，照抄真值常数即可）。

**目录 CRC** = `crc7950` 逐 32 位字，盐 `"ADEC"`：
```python
crc = crc7950(0xFFFFFFFF, count_4B + entries)
crc = crc7950(crc, b"ADEC")
```
用逐字节 CRC 算目录 CRC **必定打不开**。

### `.pa` 页面

```
0x00..0x43  头部 0x44 字节
0x44..      控件索引块（每控件 12B，不含页面组）
其后        组数据：页面组在前，随后各控件组，首尾相接
```

| 对象 | type | 组头 | 属性数 | 事件槽 |
|---|---|---|---|---|
| 页面 | `0x79` | `att-28` | 28 | 5 个 |
| 文本 | `0x74` | `att-39` | 39 | 2 个 |
| **数字** | **`0x36`** | `att-39` | 39 | 2 个 |
| 图片 | `0x70` | `att-22` | 22 | 2 个 |
| 按钮 | `0x62` | `att-42` | 42 | 2 个 |

> 数字控件的 type 是 `0x36`，**不是** `0x6E` —— 写错则控件静默失效。

头部 `+0x00` 校验值 = 5 段累积 CRC（`tjc_crc32`，多项式 `0x04C11DB7`、MSB-first、
无反射，**与标准 zlib.crc32 不同**）。

### 图片三件套

一张图需要 `.i` + `.is` + `.ib` **三个成员**，且 **`main.HMI` 名字表只登记 `.i`**：

- `.i` —— 屏显格式，画布渲染的真正入口：24B 头 + 20B 零 + 宽×高×2 原始 RGB565 小端
- `.is` / `.ib` —— 27B 头 + 完整 PNG 原文
- **⚠ `.i` 是 RGB565，没有 alpha 通道**：透明像素会变成 `0x0000` = 黑，
  画布上所有透明底图片四周带黑边。**素材必须全不透明。**

## MCU 侧：指令与回传

```c
// 每条指令末尾必须补 3 个 0xFF，缺一不可
tjc_send("n0.val=7");        // 数字控件用 .val
tjc_send("t1.txt=\"BOTTLE\""); // 文本控件用 .txt（必须带双引号）
```

五条铁律：
1. 每条指令末尾补 **3 个 `0xFF`**
2. 参数只用**十进制或颜色代号**，**不支持 `0x` 前缀**
3. 写字符串**必须带双引号**
4. 控件名**大小写敏感**，建议带页面前缀（`main.t1`）
5. **数字控件用 `.val=`，文本控件用 `.txt=`** —— 用错静默失效

`sendkey=1` 只是触摸时往串口发 7 字节包（`0x65 页 控件 事件 FF FF FF`），
**跳页需要 MCU 收包后发 `page N` 回来**。屏内自跳页必须写控件事件代码。

详见 [`docs/PROTOCOL.md`](docs/PROTOCOL.md)。

## 回归测试为什么可信

`verify_truth.py` 做四件事：

1. 对真值 `.pa` 复算 5 段累积 CRC → 须等于文件内数值
2. 对真值 `main.HMI` 复算五段累积 CRC → 同上
3. **容器克隆**：用真值成员重建 CFS 容器 → 须与真值工程**逐字节一致**
4. `.i` 互检：`payload[20:]` 须等于同编号 `.is` 转出的 RGB565

第 3 项是最强证据：生成器把真值工程完整重建出来且一个字节不差，
说明容器层实现 100% 正确。**只有它通过，才允许替换内容生成正式工程。**

```
1) .pa 头部校验值        [PASS] stored=0x2364D04F calc=0x2364D04F
2) main.HMI 五段 CRC     [PASS] stored=0x7A9C8DA2 calc=0x7A9C8DA2
3) 容器克隆逐字节一致     [PASS] gen=7341339 truth=7341339
4) .i 屏显图互检         [PASS] 13/13
```
